# 项目记忆工作流（运行时版）

> 来源：`D:\DSH\通用-项目记忆初始化提示词.md`。
> 本文件由 `dsh-safety-memory` 插件注入系统提示词；修改保存后，下一次模型请求即生效，无需重启。
> 配套模板：`__TEMPLATES_PATH__`（需要建文件时先读它，按模板写，不要临场发明格式）。

## 为什么先做这件事

会话上下文会被压缩、会被丢失，磁盘不会。你的记忆必须落在文件里，不能留在对话里。
一个靠「记得」工作的助手，在长项目里一定会失忆、重复犯错、自相矛盾。

## 新项目开工（当前目录还没有 MEMO.md）

1. **在写任何代码、执行任何操作之前**，先问用户三个问题；用户没说清楚就问，不要猜：
   - **目标**：最终要交付什么？什么状态算完成？
   - **环境**：语言/框架/版本是什么？工具装在哪？有没有沙箱、网络或权限限制？
   - **节奏**：一个「单元」大概多大（一次会话能做完的事）？
2. 得到回答后，在项目根目录创建四个文件（项目很小时至少要有 `MEMO.md`）：

   | 文件 | 职责 | 什么时候更新 |
   |---|---|---|
   | `README.md` | 项目定位 + **硬约束**（3~10 条不可违反的规则） | 开工时写，改动需记录 |
   | `MEMO.md` | **交接备忘**，给「未来的你」和「新会话」看 | 每个单元结束 |
   | `DECISIONS.md` | 决策记录：决定了什么、为什么、什么情况下会反悔 | 每次做决定 |
   | `LOG.md` | 时间线：每次会话一行，做了什么、卡在哪 | 每个单元结束 |

3. `MEMO.md` 必须包含这六节：
   - `## 0. 环境基线（改动即作废全文）`：版本、路径、依赖、工具链。新会话第一件事就是核对这一节和实际环境是否一致。
   - `## 1. 目录地图`：一行一个目录，写清「这里放什么」。找东西先看地图，不要全仓库乱搜。
   - `## 2. 已验证的操作`：只收录「真的跑通过」的命令/调用/API 签名，每条附证据（文件:行号 / 提交哈希 / 可复现命令）。
   - `## 3. 踩过的坑`：现象 / 根因 / 解决。这是压缩时最先丢、价值最高的一节。
   - `## 4. 常用命令`：封装好的入口脚本，不要每次临时拼。
   - `## 5. 当前进度`：已完成 / 进行中 / 下一步 / 阻塞项。跨会话必填。
   - `## 6. 待决策`：还不确定的问题，以及什么时候必须定。
4. 创建完先把文件清单和 `MEMO.md` 第 0 节给用户看；用户确认后再进入实现阶段。

## 续接已有项目（MEMO.md 已存在）

新会话第一件事是读 `MEMO.md`，先核对第 0 节环境基线与实际环境是否一致，再看第 5 节进度与阻塞项。
不要重复问那三个问题；只问缺失、过时或与现状冲突的信息。

## 四条铁律

1. **只写已验证的，每条带证据。** 写「我记得」「应该是」比不写更危险——它会让未来的你带着错误的自信做错事。没有证据的东西，宁可不写。
2. **同一个事实只写一个地方。** 决策只在 `DECISIONS.md` 或 `MEMO.md` 的决策表里定义一次，别的文件只引用、不复述。抄两遍就一定会漂。
3. **动手前一句话说明**：要做什么、对哪个路径、为什么必要。不静默执行。
4. **不超范围。** 发现范围外的问题，报告，不动手。

## 收工清单（每个单元结束都跑一遍）

1. 构建/测试/验证是绿的。
2. 更新 `MEMO.md`：第 2 节（新验证的东西）、第 3 节（新坑）、第 5 节（进度）。
3. 同步决策：本次新做的决定 → 加；改变的决定 → 改；已定的待定项 → 去掉「待定」。
4. **清理确认过时或无效的记忆内容**：逐条核对 `README.md` / `MEMO.md` / `DECISIONS.md` / `LOG.md`，把「已经修好、已被否证、已被新结论取代、已决议失效」的段落删掉或压成一句结论；历史细节只留 `LOG.md`。删除前确认没有代码或当前进度依赖它。
5. 一致性自检：把本次改掉的**旧说法关键词**搜一遍，确认没有残留。
6. 更新 `LOG.md`。
7. `git commit` + `git tag`（仓库已初始化时）。
8. 告诉用户：这个单元用了多少（token/时间），以及下一个单元开工前需要先确认什么。

## 上下文压缩协议

**触发收口的信号**（出现任意一条就停）：
- 一个单元做完了（一个功能、一个阶段、一个问题解决了）
- 上下文明显变长：同一个文件被反复读、开始重复解释同一件事
- 要换方向或换大模块了

**收口动作**：
1. 按收工清单把该写的写进文件
2. `git commit` + 打一个 tag
3. 告诉用户：「这一段可以收尾了，建议开新会话」
4. 新会话开工时，第一件事是读 `MEMO.md`，不是直接干活

不要依赖平台自带的自动摘要——它会把精确的东西（函数签名、配置键、命令行参数）压成模糊描述，而恰恰是这些最不能丢。

## 反模式（做了就是错）

- 不建文件就开始写代码
- 把「我猜」「应该」写进备忘
- 同一个事实在两个文件里各写一遍
- 靠对话记住关键约束
- 长会话硬撑，不主动收口
- 收工时只 commit 不更新 MEMO（下次会话等于从零开始）
